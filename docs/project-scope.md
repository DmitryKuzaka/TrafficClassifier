# TrafficClassifier — цель и границы проекта

Задача P01. Согласованная основа первой версии учебного проекта.

## Цель

Создать локальную программу, которая с помощью собственной нейросети 1D-CNN определяет категорию сетевого потока по характеристикам его первых пакетов: видео, голосовой звонок или передача файлов.

Исследовать, как качество распознавания меняется при использовании первых 8, 16, 32 и 64 пакетов. Сохранять сетевые записи и предсказания в ClickHouse, чтобы анализировать количество потоков и объём данных по категориям.

Практический смысл — помогать понимать состав наблюдаемого трафика по характеру обмена данными.

## Основные понятия

- **Пакет** — одна порция данных, переданная по сети.
- **Поток** — последовательность пакетов, относящихся к одному сетевому обмену. Один поток не обязательно соответствует всему сеансу работы приложения.
- **Признак** — характеристика пакета, которую получает модель.
- **Метка** — известная категория потока, используемая при обучении и проверке.
- **Классификация** — выбор одной из заданных категорий по признакам.

Один пример для модели — начало одного потока. Одно предсказание — категория этого потока.

## Данные

Источник — [VNAT от MIT Lincoln Laboratory](https://www.ll.mit.edu/r-d/datasets/vpnnonvpn-network-application-traffic-dataset-vnat), подготовленные последовательности из HDF5.

Рабочая выборка включает три категории без VPN: просмотр видео, голосовую связь и передачу файлов. Проверку файла, состав групп и ограничения учебного пилота смотри в разделах P04–P06 [разбора по тикетам](code-walkthrough.md).

## Входные данные

Для одного потока берём первые N пакетов в порядке их появления, где N равно 8, 16, 32 или 64. Каждый пакет представлен тремя характеристиками:

| Характеристика | Смысл |
|---|---|
| Размер | Размер пакета в байтах |
| Направление | В какую из двух сторон обмена передан пакет |
| Интервал | Время с предыдущего пакета; для первого пакета принимаем ноль |

Входные интервалы измеряются в миллисекундах. Направление `1` совпадает с направлением первого пакета, `0` означает обратную сторону. При нормализации параметры размеров и интервалов рассчитываются только по обучающим данным.

Короткие последовательности дополняем до выбранной длины. Отдельная маска отмечает настоящие пакеты, чтобы заполнение исключалось при обработке сетью и усреднении.

Содержимое пакетов, IP-адреса, порты, имена файлов, идентификаторы захватов и правильная метка не входят в признаки нейросети. Для раннего распознавания также не используем сведения о пакетах после первых N.

## Результат работы

Программа возвращает одну из трёх категорий и оценки классов. Оценки показывают предпочтение модели; их не трактуем как проверенную вероятность правильного ответа.

Вместе с предсказанием сохраняем идентификатор потока, версию модели и использованное N. Это позволяет различать результаты разных экспериментов и корректно считать статистику в ClickHouse.

Первая версия выбирает среди трёх известных категорий. Качество на других видах трафика отдельно не подтверждено.

## Пример использования

1. Берём поток из тестовой части VNAT с известной категорией, которую скрываем от модели.
2. Выделяем первые 32 пакета и подготавливаем их размеры, направления и интервалы.
3. Загружаем сохранённую нейросеть и получаем предсказанную категорию.
4. Сравниваем предсказание с известной меткой для оценки качества.
5. Сохраняем результат в ClickHouse и учитываем его в аналитике выбранного эксперимента.

Основной путь данных: запись потока → первые N пакетов → подготовка признаков → нейросеть → категория → ClickHouse → статистика.

## Роли технологий

| Технология | Роль в проекте |
|---|---|
| Python | Чтение и подготовка данных, объединение частей программы |
| PyTorch | Создание, обучение и применение собственной 1D-CNN |
| ClickHouse | Хранение потоков и предсказаний, SQL-аналитика по категориям и объёму данных |
| FastAPI | Небольшой локальный API: принять характеристики пакетов и вернуть предсказание |

Обучение выполняется в Python/PyTorch на подготовленной выборке. При обычном запросе программа использует сохранённую модель.

## Эксперимент и оценка качества

Главный вопрос: как меняется качество классификации при N = 8, 16, 32 и 64?

Основная метрика — **macro-F1**: качество каждого класса учитывается с одинаковым весом. Дополнительно показываем precision, recall и F1 по классам, а также матрицу ошибок — таблицу правильных и ошибочных предсказаний.

Для сравнения обучаем Random Forest на сводных характеристиках тех же первых N пакетов. Основная нейросеть проекта — 1D-CNN; её преимущество проверяем экспериментом.

Общие правила проверки:

- Разделяем данные на обучающую, проверочную и итоговую части — train, validation и test — по независимым группам записей.
- Связанные захваты, VPN/non-VPN варианты одного обмена и все префиксы одного потока остаются в одной части.
- Выбираем настройки по train/validation. Итоговые модели и правила сравнения фиксируем перед оценкой на test.
- Для разных N и обеих моделей используем одинаковые группы проверки; долю коротких потоков показываем отдельно.
- В аналитике выбираем конкретную модель, N и запуск эксперимента. Повторные предсказания одного потока не должны многократно увеличивать объём трафика.

Выводы относятся к проверенным записям VNAT. Конкретное значение качества и переносимость на другие сети определяются результатами экспериментов.

## Границы первой версии

В первую версию входят:

- локальная работа с готовыми сетевыми записями VNAT;
- проверка данных и подготовка признаков первых пакетов;
- обучение собственной 1D-CNN и контрольное сравнение с Random Forest;
- эксперимент с 8, 16, 32 и 64 пакетами;
- хранение и SQL-аналитика в ClickHouse;
- небольшой локальный API и демонстрация результата с простой статистикой;
- инструкция по воспроизводимому запуску.

За пределами первой версии:

- захват трафика из живой сети;
- обнаружение атак и блокировка соединений;
- определение точного приложения или содержимого обмена;
- распознавание произвольных неизвестных категорий;
- аккаунты пользователей и многопользовательская авторизация;
- Telegram-бот;
- публичное размещение сервиса.
