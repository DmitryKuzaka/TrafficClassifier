# TrafficClassifier — план проекта для Jira

Состояние: план подготовлен локально. Проект, эпики и задачи в Jira ещё не созданы. Ключи P01–P36 и M0–M5 — локальные обозначения плана, а не номера Jira.

## Цель проекта

Обучить собственную 1D-CNN определять категорию сетевого соединения по характеристикам первых пакетов: просмотр видео, голосовая связь или передача файлов. Исследовать качество по первым 8, 16, 32 и 64 пакетам. Использовать ClickHouse для хранения записей, предсказаний и аналитики; предоставить небольшой локальный API и демонстрацию.

План рассчитан на одного исполнителя. Ориентир — шесть недель при регулярной работе. Сумма предварительных оценок: **77 часов активной работы**, плюс резерв на освоение новых понятий, исправления и ожидание обучения. Оценки не являются обещанием срока: после проверки данных и первого обучения их следует уточнить.

## Границы первой версии

- Данные: [VNAT, MIT Lincoln Laboratory](https://www.ll.mit.edu/r-d/datasets/vpnnonvpn-network-application-traffic-dataset-vnat), подготовленные последовательности из HDF5. Фактический состав и условия использования проверяются в M0.
- Вход нейросети: размеры, направления и интервалы первых N пакетов. Содержимое пакетов, IP-адреса, порты, имена файлов и идентификаторы захватов не являются признаками модели.
- Работа с историческими записями. Лабораторное качество не означает подтверждённую работу в любой современной сети.
- ClickHouse хранит данные и рассчитывает SQL-аналитику; обучение выполняет Python/PyTorch.
- Основная модель — обучаемая с нуля 1D-CNN. Random Forest нужен для сравнения на тех же префиксах и разбиениях.
- Запуск локальный. Живой перехват, обнаружение атак, блокировки, Telegram, многопользовательская авторизация и публичное размещение вынесены за границы MVP.

Стартовая сеть: **3 входных канала → Conv1d(16 фильтров, окно 3) → ReLU → Conv1d(32 фильтра, окно 3) → ReLU → усреднение с маской → Linear(32→16) → ReLU → Dropout(0.2) → Linear(16→3)**. Для обеих свёрток padding=1. В такой конфигурации 2307 обучаемых параметров. На обучении используются сырые оценки и CrossEntropyLoss; softmax применяется при выдаче оценок классов.

## Общие правила эксперимента

1. Фиксируем независимые группы записей и разбиение один раз. Связанные захваты, VPN/non-VPN варианты одного обмена и префиксы одного соединения не расходятся между train, validation и test.
2. Предобработка и её параметры рассчитываются по train. Метки, служебные поля и будущие пакеты не попадают в признаки.
3. CNN и Random Forest получают сведения об одних и тех же первых N пакетах. Полная длительность соединения или последующие пакеты не используются для ранней классификации.
4. Короткие соединения дополняются с маской. Для всех N сохраняются одинаковые группы проверки; доля коротких записей показывается отдельно. Если добавляется сравнение только достаточно длинных соединений, поднабор фиксируется одинаково для всех N.
5. Настройки и checkpoints выбираются по train/validation. До оценки test фиксируются все итоговые модели и протокол. После открытия test результат не превращается в инструмент дальнейшего подбора.
6. Основная метрика — macro-F1. Также показываются результаты по классам и матрица ошибок. Высокая accuracy сама по себе недостаточна.
7. Уникальность и повторяемость импорта обеспечиваются явно: MergeTree не вводит уникальное ограничение на flow_id.
8. В аналитике выбран один run_id/model_id/N. Несколько предсказаний одного соединения не должны многократно увеличивать объём трафика.
9. Превосходство нейросети, точность на неизвестных типах и научная новизна не обещаются заранее.

## Как работать по плану

Статусы: **Backlog → Ready → In Progress → Review → Done**. Названия подстраиваются под доступный workflow нового проекта Jira.

- Одновременно держать в работе одну основную задачу.
- Перед началом: прочитать описание, разобрать новые понятия, проверить зависимости и своими словами объяснить ожидаемый результат.
- После реализации: показать изменение, относящиеся к нему проверки и объяснение решения. Ревью ориентируется на критерии готовности тикета.
- Если задача занимает заметно больше одного вечера, разделить её на независимые результаты и обновить оценку.
- На конце каждого этапа продемонстрировать его результат и скорректировать следующие оценки.
- Тесты добавляются там, где проверяют существенную ошибку: разбиение, нормализацию, маски, повторяемость импорта, сохранение модели и HTTP-контракт. Каждый график отдельным тестом не покрывается.
- CI выполняет быстрые проверки на маленьких искусственных данных; полный датасет и обучение запускаются отдельно.
